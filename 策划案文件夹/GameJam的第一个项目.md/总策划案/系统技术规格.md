# 系统技术规格

## 第0章: 文档约定

| 策划案描述 | UE5 对应 | 说明 |
|-----------|----------|------|
| 玩家主界面 (\*1\*) | `L_MainMenu`（独立关卡） | 纯UMG界面，无3D场景 |
| 玩家玩的以B为主角的游戏 (\*2\*) | `L_BGameplay`（持久关卡） | 3D第一人称，主游戏场景 |
| B玩的游戏主界面 (\*3\*) | `WBP_ConsoleUI`（UMG Widget） | 覆盖在L2之上的UI层 |
| B玩的以A为主角的游戏 (\*4\*) | `L_AGameplay`（子关卡或RenderTarget） | 嵌套游戏内容，暂缓设计 |
| 拿出/收起游戏机 | 游戏机组件状态切换 | L2↔L3的触发动作 |
| 存档 | SaveGame 对象 | 持久化数据容器 |
| 旧存档 | 带锁定标记的存档槽 | 初始存在，通关前不可操作 |
| 游魂 | 敌人AI | 追踪玩家的不可见敌人 |
| 夺舍 | 叙事事件触发 + 存档删除检测 | 核心剧情机制 |
| 元气/精力 | float 变量 0~1 | 影响移动速度、画面后处理 |
| 契印 | NarrativeFlag 中的一个标记 | 剧情关键标记 |

### 通用约定

- **L1 / L2 / L3 / L4** = Layer 1~4，对应上述四个层级
- **BP_** = Blueprint 蓝图类
- **WBP_** = Widget Blueprint 控件蓝图
- **策划引用**: 文档中 `>>` 开头的引用块表示来自策划文档的原文约束
- **待确认**: `[待确认]` 标记表示需要与策划确认后才能落地的技术决策
- **暂缓**: `[暂缓]` 标记表示当前版本不做，但预留接口

## 第1章: 总体架构 — **Sky 负责**

### 1.1 四层嵌套模型

```
┌─────────────────────────────────────────┐
│ LAYER_1 — MainMenu                      │
│ 独立关卡，纯UMG                         │
│ ├── 存档管理                            │
│ ├── 设置                                │
│ └── 退出游戏                            │
├─────────────────────────────────────────┤
│ LAYER_2 — OuterGameplay                 │
│ 3D持久关卡，B为主角                     │
│ ├── 运动 / 交互 / 敌人AI / 菜单        │
│ └── [空格] → 进入 L3                    │
├─────────────────────────────────────────┤
│ LAYER_3 — ConsoleUI                     │
│ UMG覆盖层，L2之上                       │
│ └── 与L1一致的存档/主菜单界面            │
├─────────────────────────────────────────┤
│ LAYER_4 — InnerGameplay                 │
│ A为主角的嵌套游戏内容 [暂缓]            │
└─────────────────────────────────────────┘
```

### 1.2 层级切换路径

```
允许的转移:
  L1 ←→ L2    (读档进入 / 退出到主菜单)
  L2 ←→ L3    (空格键，运行时切换)
  L3 ←→ L4    (L3内选择读档 / L4内退出)

不允许的转移:
  L1 → L3/4   (必须先经过L2)
  L2 ←→ L4    (必须经过L3中转)
```

**约束**:
- L2 ↔ L3 切换时，**L2 世界持续运行**（Tick不暂停、AI继续、物理继续）
- L2 内打开 ESC 菜单时，**L2 世界暂停**（使用 Set Global Time Dilation 设为 0）
- 菜单暂停 ≠ 游戏机不暂停，这是两个独立机制

### 1.3 关卡与资源目录

```
Content/

├── Input/

## 第2章: 状态机设计 — **Sky 负责**

### 2.1 全局层级状态机

由 `BP_HorrorGameInstance` 中的层级状态管理器驱动。

```
状态枚举 (Blueprint Enum):
  STATE_MAIN_MENU         — L1 激活
  STATE_OUTER_GAMEPLAY    — L2 激活，L3/L4 不活跃
  STATE_CONSOLE_ACTIVE    — L2 运行中，L3 活跃
  STATE_INNER_GAMEPLAY    — L2 运行中，L4 活跃
  STATE_CINEMATIC         — 过场动画中（屏蔽所有输入）

转移规则:
  MAIN_MENU       → OUTER_GAMEPLAY    [Event: OnLoadGame]
  OUTER_GAMEPLAY  → MAIN_MENU         [Event: OnExitToMenu]
  OUTER_GAMEPLAY  → CONSOLE_ACTIVE    [Input: Space]
  CONSOLE_ACTIVE  → OUTER_GAMEPLAY    [Input: Space / ForcePutAway]
  CONSOLE_ACTIVE  → INNER_GAMEPLAY    [Event: OnInnerGameStart]
  INNER_GAMEPLAY  → CONSOLE_ACTIVE    [Event: OnInnerGameExit]
  ANY             → CINEMATIC         [Event: OnCutsceneTrigger]
  CINEMATIC       → 恢复到之前状态    [Event: OnCutsceneEnd]
```

**广播方式**: 每次状态变更通过 **Event Dispatcher** 广播，各蓝图自行绑定监听。

### 2.2 游戏内子状态机

仅在 `STATE_OUTER_GAMEPLAY` 和 `STATE_INNER_GAMEPLAY` 下有效，由 `BP_PlayerController` 管理。

```
子状态 (Blueprint Enum):
  SUBSTATE_NORMAL     — 自由移动、自由交互
  SUBSTATE_MENU       — ESC 菜单打开（世界暂停）
  SUBSTATE_INTERACT   — 深度交互中（解谜、阅读笔记等）
  SUBSTATE_STUNNED    — 被鬼追上昏倒/苏醒过渡

转移:
  NORMAL  ←→ MENU       [Input: ESC]
  NORMAL  ←→ INTERACT   [Event: OnInteractBegin / OnInteractEnd]
  NORMAL   → STUNNED    [Event: OnCaughtByEnemy]
  STUNNED  → NORMAL     [Event: OnWakeUp]（游魂暂归，精力恢复）
```

**状态行为表**:

| 子状态 | 移动 | 交互 | 拿出游戏机 | 世界Tick | 光标 |
|--------|------|------|-----------|----------|------|
| NORMAL | ✅ | ✅ | ✅ | 正常 | 隐藏 |
| MENU | ❌ | ❌ | ❌ | 暂停* | 显示 |
| INTERACT | ❌ | ❌ | ❌ | 正常 | 视情况 |
| STUNNED | ❌ | ❌ | ❌ | 正常 | 隐藏 |

> \* 菜单暂停世界：使用 Set Global Time Dilation = 0  
> \*\* 游戏机激活时：世界不暂停，但玩家移动禁用

### 2.3 菜单暂停 vs 游戏机不暂停

| 场景 | L2 世界 | L2 玩家移动 | L3/L4 | 实现方式 |
|------|---------|------------|-------|----------|
| 正常游玩 | Tick | 可用 | 不活跃 | 默认 |
| ESC 菜单 | **暂停** | 禁用 | 不活跃 | Set Global Time Dilation = 0 |
| 拿出游戏机(L3) | **继续Tick** | **禁用** | 活跃 | 只禁用 Character Movement |
| 玩嵌套游戏(L4) | **继续Tick** | **禁用** | 活跃 | 只禁用 Character Movement |

## 第3章: 输入系统 — **Sky 负责**

### 3.1 Enhanced Input

| 优先级 | Context名称 | 包含的 Actions | 激活条件 |
|:---:|---|------|---|
| 0 (最高) | `IMC_Cinematic` | SkipCutscene | 过场动画中 |
| 1 | `IMC_Menu` | UIConfirm, UICancel, Navigate | ESC菜单打开 |
| 2 | `IMC_ConsoleUI` | UIConfirm, UICancel, Navigate, ConsoleBack | L3/L4 激活 |
| 3 (最低) | `IMC_Gameplay` | Move, Look, Interact, ToggleConsole, Menu | L2 正常游玩 |

### 3.2 Input Action 定义表

| Action名称 | 值类型 | 绑定按键 | 说明 |
|-----------|--------|---------|------|
| `IA_Move` | Axis2D | W/S/A/D | WSAD移动 |
| `IA_Look` | Axis2D | Mouse XY | 视角旋转 |
| `IA_Interact` | Digital (bool) | E | 交互 |
| `IA_ToggleConsole` | Digital (bool) | Space | 拿出/收起游戏机 |
| `IA_Menu` | Digital (bool) | ESC | 打开/关闭菜单 |
| `IA_UIConfirm` | Digital (bool) | Enter / 鼠标左键 | UI确认 |
| `IA_UICancel` | Digital (bool) | ESC / Backspace | UI取消/返回 |

### 3.3 上下文切换逻辑（蓝图实现）

```
BP_PlayerController 中的 OnLayerStateChanged 事件:

  Switch on NewState:
    OUTER_GAMEPLAY:
      → Remove All Mapping Contexts
      → Add Mapping Context: IMC_Gameplay (Priority 3)
      → Set Show Mouse Cursor: false
      
    CONSOLE_ACTIVE:
      → Remove All Mapping Contexts
      → Add Mapping Context: IMC_Gameplay (Priority 3)  [可选，保留底层]
      → Add Mapping Context: IMC_ConsoleUI (Priority 2)
      → Call BP_PlayerCharacter.DisableMovement
      → Set Show Mouse Cursor: true
      
    INNER_GAMEPLAY:
      → Remove All Mapping Contexts
      → Add Mapping Context: IMC_ConsoleUI (Priority 2)
      → Call BP_PlayerCharacter.DisableMovement
      
    MAIN_MENU:
      → Remove All Mapping Contexts
      → Add Mapping Context: IMC_Menu (Priority 1)
      → Set Show Mouse Cursor: true
```

### 3.4 输入冲突处理原则

- `IA_Move`/`IA_Look` 不与其他 Action 冲突
- **Space**：在 IMC_Gameplay 中触发拿出/收起游戏机；在 IMC_ConsoleUI 中触发返回L2
- **ESC**：仅在 L2/L4 的游戏状态下可用 → 打开菜单；菜单打开 → 关闭菜单（L1/L3 下 ESC 行为由各自 UI 层处理）
- **E**：仅在 `SUBSTATE_NORMAL` 且检测到可交互对象时生效

## 第4章: 层级间事件流 — **Sky 负责**

### 4.1 事件分发器定义

所有跨层级通信通过 Event Dispatcher 进行，**禁止蓝图间直接引用（Hard Reference）**。

在 `BP_HorrorGameInstance` 中创建以下 Event Dispatcher:

| Dispatcher名称 | 参数 | 用途 |
|---------------|------|------|
| `OnLayerChanged` | FromLayer (int), ToLayer (int) | 层级切换 |
| `OnConsoleToggled` | bConsoleActive (bool) | 游戏机拿出/收起 |
| `OnForceConsolePutAway` | (无) | 脚本强制收起游戏机 |
| `OnSaveCreated` | SlotName (String) | 存档创建 |
| `OnSaveDeleted` | SlotName (String) | 存档删除 |
| `OnGameLoaded` | SlotName (String) | 读档完成 |
| `OnNarrativeFlagSet` | FlagName (Name) | 叙事标记被设置 |
| `OnGameCompleted` | (无) | 游戏通关 |

### 4.2 数据流向图

```
[BP_HorrorGameInstance]
       |
       |-- 持有: 当前层级状态 (Enum 变量)
       |-- 持有: 叙事标记表 (Map<Name, Bool>)
       |-- 持有: 存档槽信息
       |
       | 广播 Event Dispatchers
       v
[L1: MainMenu Widgets] ←→ [L2: BP_PlayerController + BP_PlayerCharacter]
                                    |
                              [游戏机组件] ←→ [L3: WBP_ConsoleUI]
                                                    |
                                              [L4: 嵌套游戏内容]
```

### 4.3 关键场景数据流

#### 场景A: 玩家读档进入游戏

1. L1 Widget → 调用 `BP_HorrorGameInstance` 中的 Load Game 函数
2. 从磁盘加载 SaveGame 对象，恢复 NarrativeFlags
3. 设置层级状态为 `OUTER_GAMEPLAY`
4. Open Level → `L_BGameplay`
5. `BP_OuterGameplayGameMode` 的 Event BeginPlay → 从 SaveGame 恢复玩家位置、世界状态
6. 广播 `OnGameLoaded`

#### 场景B: 按下空格拿出游戏机

1. `IA_ToggleConsole` 触发 → 游戏机组件中的 Toggle 事件
2. 播放拿出动画（如有）
3. 动画进度到一半时：设置层级为 `CONSOLE_ACTIVE`
4. 显示 `WBP_ConsoleUI`
5. 禁用 BP_PlayerCharacter 的移动
6. 广播 `OnConsoleToggled(true)`
7. **L2 世界继续 Tick**

#### 场景C: 脚本强制收起游戏机

1. 关卡蓝图（或任何触发器）→ 调用 `BP_HorrorGameInstance` 的 ForceConsolePutAway
2. 无论当前在 L3 还是 L4 → 直接切回 L2
3. 隐藏 `WBP_ConsoleUI`
4. 恢复 BP_PlayerCharacter 的移动
5. 设置层级为 `OUTER_GAMEPLAY`
6. 广播 `OnForceConsolePutAway` + `OnConsoleToggled(false)`

## 第5章: 存档系统 — **震Y 负责**

### 5.1 SaveGame 数据结构

创建 **`BP_MetaHorrorSaveGame`** 蓝图类（父类：SaveGame），包含以下变量：

| 变量名 | 类型 | 用途 |
|--------|------|------|
| `SlotName` | String | 槽名称，"PlayerSave" 或 "OriginalSave" |
| `DisplayName` | String | UI 显示名称 |
| `bIsPreExistingSave` | Boolean | 是否为旧存档 |
| `bCanBeDeleted` | Boolean | 是否允许删除 |
| `bCanBeRead` | Boolean | 是否允许读取 |
| `CreatedAt` | DateTime | 创建时间 |
| `LastSavedAt` | DateTime | 最后保存时间 |
| `TotalPlayTimeSeconds` | Float | 累计游玩时间 |
| `PlayerTransform` | Transform | 玩家位置/旋转 |
| `NarrativeFlags` | Map (Name → Boolean) | 叙事标记 |
| `GameCompletionPercent` | Float (0~1) | 通关进度 |
| `bHasCompletedGame` | Boolean | 是否已通关 |
| `SoulFragmentationLevel` | Float (0~1) | 灵魂分裂程度 |
| `bOriginalSoulReleased` | Boolean | 旧存档灵魂是否已释放 |

### 5.2 存档槽管理

`BP_HorrorGameInstance` 维护固定两个槽：

| 索引 | SlotName | 可否创建 | 可否删除 | 可否读取 | 说明 |
|:---:|---|:---:|:---:|:---:|---|
| 0 | `OriginalSave` | ❌ 初始存在 | ❌ 通关前 / ✅ 通关后 | ❌ 通关前 / ✅ 通关后 | 旧存档 |
| 1 | `PlayerSave` | ✅ | ✅ | ✅ | 玩家存档 |

> **简化理解**：可以认为只有一个有效档位（PlayerSave）。旧存档（OriginalSave）在通关前基本是"摆设"——不可读、不可删，仅作为剧情叙事的锚点存在。通关后解锁全部操作。

### 5.3 存档操作流程

#### 创建存档

1. L1 中点击空档位 → 弹出 `WBP_CreateSaveDialog`："是否创建你的存档？" [是] [否]
   - "[否]" 或 **"返回"按钮始终可用**，可随时返回上一级（所有存档相关UI均遵守此规则）
2. 选"是" → GameInstance 中调用 Create New Save Game 节点
3. 初始化变量默认值 → Save Game to Slot 写入磁盘
4. 刷新 UI 档位状态
5. 广播 `OnSaveCreated`

#### 保存游戏

- **手动保存**: ESC 菜单点击"保存游戏"
- **自动保存**: 触发于——
  - 关键叙事标记被设置时
  - 玩家进入特定 Trigger Volume
  - 定时器（可配置间隔，默认 5 分钟）
- 使用 **Save Game to Slot** 节点覆盖写入
- 显示低调的自动保存指示器（2秒渐隐）

#### 删除存档

1. 选中存档 → 点击"删除"（**删除按钮需做弱化处理**：暗色 + 比读取键小的尺寸，防止误触）
2. 弹出 `WBP_DeleteSaveDialog`（二级确认弹窗，防止误删）
3. 选"是" → 检查 `bCanBeDeleted`：
   - 旧存档 + 未通关: **拒绝** — 按钮红亮 + 禁止音效
   - 玩家存档 / 旧存档+已通关: 允许
4. 使用 **Delete Game in Slot** 节点删除
5. 如果删除的是旧存档且已通关: **触发结局叙事** → 广播 `OnGameCompleted`

#### 旧存档交互规则

```
旧存档 始终可见:
  - 通关前: "读取"和"删除"按钮灰色且无响应，点击后红亮+禁止音效
  - 通关后: 两个按钮全部解锁
```

## 第6章: 敌人AI — **震Y 负责**

### 6.1 蓝图架构

```
BP_EnemyPawn (父类: Character 或 Pawn)
├── CapsuleComponent            — 碰撞
├── CharacterMovementComponent  — NavMesh 寻路
└── (无 Mesh)                   — 运行时不可见

> 策划未强制要求使用 Character，只要满足寻路追踪需求，使用更轻量的 Pawn 亦可。

BP_EnemyAIController (父类: AIController)
├── AIPerceptionComponent
│   ├── AI Sight Config
│   └── AI Hearing Config
├── BehaviorTreeComponent
└── BlackboardComponent
    ├── Key: TargetPlayer (Object)
    ├── Key: LastKnownLocation (Vector)
    ├── Key: CurrentAIState (Enum: Idle/Investigating/Chasing/Stalking)
    ├── Key: bHasLineOfSight (Bool)
    └── Key: AlertLevel (Float 0~1)
```

> 使用 AIController + BehaviorTree 是因为 UE5 的 NavMesh 寻路、EQS（环境查询系统）和 BehaviorTree 工具链对这套方案支持最好。所有配置在蓝图中完成，无需手写代码。

### 6.2 感知配置

#### AI Sight（视觉感知）

| 参数 | 值 | 说明 |
|------|-----|------|
| SightRadius | 1500 | 远距离即可察觉 |
| LoseSightRadius | 2000 | 更难摆脱 |
| PeripheralVisionAngleDegrees | 90° | 宽视野 |
| AutoSuccessRangeFromLastSeenLocation | 500 | 失去视线后的宽容范围 |

#### AI Hearing（听觉感知）

| 参数 | 值 | 说明 |
|------|-----|------|
| HearingRange | 3000 | 大范围听觉 |
| LoSHearingRange | 5000 | 隔墙也能感知大致方向 |
| MaxNoiseAge | 10秒 | 噪音信息保留时间 |

**噪音标签**（通过 **Report Noise Event** 节点触发）:

| 噪音标签 | 范围 | 触发场景 |
|----------|------|---------|
| `Noise_Footstep_Walk` | 500 | 玩家走路 |
| `Noise_Footstep_Run` | 1200 | 玩家跑步 |
| `Noise_DoorOpen` | 2000 | 开门 |
| `Noise_ObjectDrop` | 1500 | 物体掉落 |

### 6.3 Behavior Tree 结构

```
Root (Selector)
│
├── [Sequence] ▸ Chase (追赶) — 优先级最高
│   ├── Decorator: HasLineOfSight?
│   ├── Task: UpdateLastKnownLocation
│   ├── Task: MoveDirectlyToward (全速)
│   └── Task: PlayChaseAudio
│
├── [Sequence] ▸ Investigate (调查)
│   ├── Decorator: HasLastKnownLocation OR HasHeardNoise?
│   ├── Task: MoveToLastKnownLocation
│   ├── Task: Rotate to Face Last Location (随机巡视)
│   └── Wait: 3~8 秒
│
├── [Sequence] ▸ Stalk (尾随/制造恐怖)
│   ├── Decorator: NOT PlayerIsAware
│   ├── Decorator: Distance > 800
│   ├── Task: MoveNearPlayer (保持距离, 避开视线)
│   └── Task: TriggerAmbientEvent (播放响声/挪动物体)
│
└── [Sequence] ▸ Patrol / Idle
    ├── Task: GetNextPatrolPoint
    └── Task: MoveToPatrolPoint
```

### 6.4 关键约束

| 约束 | 说明 |
|------|------|
| **单AI** | 只存在一个敌人实例 |
| **不可见** | Mesh = None，依赖3D音频提示位置 |
| **追上了不GameOver** | 触发昏倒→苏醒流程（游魂暂归机制） |
| **剧本干预** | 蓝图接口：`ForceSetAIState(NewState)` |
| **随叙事变化** | AI 监听 `OnNarrativeFlagSet`，行为随进度改变 |
| **Console激活时** | AI 继续运行但可降低 Tick 频率（Set Actor Tick Interval = 0.2s） |

### 6.5 昏倒/苏醒机制

```
被敌人追上:
  1. 播放贴脸惊吓音效 + 屏幕淡黑
  2. 切换到 SUBSTATE_STUNNED
  3. 等待 N 秒（可配置变量，建议 3~5 秒）
  4. 屏幕渐亮，玩家在附近安全位置醒来
  5. SoulFragmentationLevel 临时回退
  6. 广播 OnWakeUp (Event Dispatcher)
  7. 切换到 SUBSTATE_NORMAL
```

## 第8章: 交互系统 — **罗非鱼 负责**


### 8.1 蓝图接口定义

创建 **`BPI_Interactable`**（Blueprint Interface），包含以下函数：

| 接口函数 | 输入 | 输出 | 用途 |
|---------|------|------|------|
| `OnInteract` | Interactor (Actor) | — | 核心交互逻辑，玩家按E时调用 |
| `CanInteract` | Interactor (Actor) | Boolean | 条件门控，当前是否可交互 |
| `GetInteractPrompt` | — | Text | 返回如 "按E开门" "按E阅读" 的提示文本 |
| `OnHoverBegin` | Interactor (Actor) | — | 准星进入范围时的回调 |
| `OnHoverEnd` | Interactor (Actor) | — | 准星离开范围时的回调 |

**使用方法**:
1. 任何需要交互的Actor（门、笔记、物品等）在 Class Settings 中添加 `BPI_Interactable` 接口
2. 在蓝图内实现上述5个函数
3. 交互检测组件通过 Line Trace 找到实现了该接口的 Actor 后，直接调用接口函数

### 8.2 交互检测组件

在 `BP_PlayerCharacterB` 上挂载一个 **ActorComponent**（命名为 `InteractionComponent`）：

```
Event Tick 中执行:
  1. LineTraceByChannel 从摄像机位置向前
     ├── 距离: 250 单位 (可配置变量)
     ├── 通道: Visibility (或自定义 Interactable 通道)
     └── 输出: HitResult
     
  2. 检查 Hit Actor 是否实现了 BPI_Interactable:
     ├── 是 且 首次命中该Actor:
     │   ├── 调用 OnHoverBegin (接口函数)
     │   ├── 调用 GetInteractPrompt → 显示 WBP_InteractionPrompt
     │   └── 缓存当前 Hit Actor
     │
     ├── 是 且 持续命中 且 玩家按E:
     │   ├── 调用 CanInteract → 检查条件
     │   └── 条件通过 → 调用 OnInteract
     │
     ├── 命中新Actor:
     │   ├── 调用旧Actor的 OnHoverEnd
     │   └── 调用新Actor的 OnHoverBegin
     │
     └── 未命中:
         ├── 调用之前缓存的 Actor 的 OnHoverEnd
         └── 隐藏 WBP_InteractionPrompt
```

### 8.3 蓝图交互

以下是交互需要基于 `BPI_Interactable` 接口实现的交互物体：

| 交互物 | OnInteract 行为 | CanInteract 条件 | 提示文本 |
|--------|----------------|-----------------|---------|
| 门 | 开/关动画，更新 NavMesh | 未被锁 | "按E开门" |
| 笔记/文档 | 显示阅读UI | 无 | "按E阅读" |
| 可拾取物品 | 添加到背包/使用 | 背包有空间 | "按E拾取" |
| 电脑/手机 | 显示终端UI | 剧情条件满足 | "按E使用" |
| 撒作物（驱鬼） | 播放撒作物动画，创建临时安全区 | 持有作物 | "按E撒作物" |
| 特殊颜料 | 涂抹表面使鬼显形 | 持有颜料，目标为玻璃/镜子 | "按E涂抹" |

### 8.4 交互系统与叙事标记的联动

交互程序可以通过检查 NarrativeFlags 来控制交互条件：

```
示例: 在 CanInteract 函数中:

## 第10章: 游戏机系统 (Console) — **Sky 负责**

### 10.1 组件设计

在 `BP_PlayerCharacterB` 上创建 **ActorComponent** 蓝图（命名为 `ConsoleComponent`）：

| 变量 | 类型 | 默认值 | 用途 |
|------|------|--------|------|
| `CurrentState` | Enum: Hidden/AnimatingOut/Active/AnimatingAway | Hidden | 当前状态 |
| `TakeOutAnimation` | AnimMontage 引用 | — | 拿出动画 |
| `PutAwayAnimation` | AnimMontage 引用 | — | 收起动画 |
| `AnimationDuration` | Float | 0.5 | 动画时长（秒） |
| `InputSwitchAtProgress` | Float | 0.5 | 动画播放到多少%时切换输入 |

**Event Dispatcher**:
| 名称 | 参数 | 用途 |
|------|------|------|
| `OnConsoleToggled` | bActive (Boolean) | 通知其他系统 |

### 10.2 拿出/收起流程

```
▸ 拿出流程:
  1. Guard: CurrentState == Hidden
  2. CurrentState = AnimatingOut
  3. 播放 TakeOutAnimation
  4. 在动画的 InputSwitchAtProgress 时刻:
     - 调用 BP_HorrorGameInstance 的层级切换 (→ CONSOLE_ACTIVE)
     - 显示 WBP_ConsoleUI
     - 调用 BP_PlayerCharacter.DisableMovement()
  5. 动画完: CurrentState = Active
  6. 广播 OnConsoleToggled(true)

▸ 收起流程:
  1. Guard: CurrentState == Active 或 L4
  2. CurrentState = AnimatingAway
  3. 播放 PutAwayAnimation
  4. 隐藏 WBP_ConsoleUI
  5. 动画完:
     - 调用层级切换 (→ OUTER_GAMEPLAY)
     - 调用 BP_PlayerCharacter.EnableMovement()
     - CurrentState = Hidden
  6. 广播 OnConsoleToggled(false)

▸ 强制收起（脚本调用）:
  1. 跳过动画（或加速至0.2秒）
  2. 立刻隐藏 WBP_ConsoleUI
  3. 立刻恢复移动 + 层级切换
  4. CurrentState = Hidden
  5. 广播 OnForceConsolePutAway + OnConsoleToggled(false)
```

### 10.3 视觉方案

**方案**: UMG 全屏覆盖 + RenderTarget 渲染 L4 3D 场景

```
WBP_ConsoleUI 布局:
  ┌──────────────────────────────────┐
  │          半透明黑色遮罩           │
  │    ┌────────────────────┐        │
  │    │                    │        │
  │    │   游戏机屏幕区域    │        │
  │    │   (容纳L3/L4内容)  │        │
  │    │                    │        │
  │    │  L3: UMG Widget    │        │
  │    │  L4: RenderTarget  │        │
  │    │    (简化3D场景)    │        │
  │    └────────────────────┘        │
  │          "按空格收起"            │
  └──────────────────────────────────┘
```

**L4 RenderTarget 方案**:

## 附录B: 蓝图通信模式速查

面向蓝图交互程序员的核心通信模式：

### B.1 Blueprint Interface（蓝图接口）

**用途**: 不同Actor之间调用统一函数，无需知道对方具体类型。

```
场景: 各种交互物体（门、笔记、物品）
实现:
  1. 创建 BPI_Interactable
  2. 添加函数 OnInteract, CanInteract, GetInteractPrompt 等
  3. 各交互Actor在 Class Settings 中添加此接口
  4. 各自实现函数逻辑
  5. 调用方: "Does Actor Implement Interface?" → "Call Interface Function"
```

### B.2 Event Dispatcher（事件分发器）

**用途**: 一对多广播，发送方不关心谁在听。

```
场景: GameInstance 广播层级切换、存档事件
实现:
  1. 在 BP_HorrorGameInstance 中创建 Event Dispatcher
  2. 发送方: Call [DispatcherName]
  3. 接收方: Bind Event to [DispatcherName] (在 BeginPlay 中)
  4. 接收方: Unbind (在 EndPlay 中)
```

### B.3 直接函数调用

**用途**: 明确的一对一通信，调用方持有目标引用。

```
场景: PlayerController 调用 PlayerCharacter 的函数
实现:
  1. Get Player Character → Cast To BP_PlayerCharacterB
  2. → Call DisableMovement / EnableMovement / SetSpeedMultiplier

注意: 仅在已持有明确引用时使用，避免在 Tick 中频繁 Cast
```

### B.4 GameInstance 中转

**用途**: 跨关卡持久通信的枢纽。

```
场景: L1的存档选择影响L2的行为
实现:
  1. L1 Widget → Get Game Instance → Cast To BP_HorrorGameInstance → SetFlag(...)
  2. L2 关卡蓝图 → Get Game Instance → Cast To BP_HorrorGameInstance → HasFlag(...)
```
